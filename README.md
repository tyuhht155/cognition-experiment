# 递归计算认知系统 — 最小可运行实验

验证一个计算理论：**基本命题形式 + 任意生成/变换 + 验证 + 价值评价 + 递归计算**，是否能够产生不断增长并不断变得有效的知识与计算能力。

> 仓库地址：https://github.com/tyuhht155/cognition-experiment

---

## 一、核心理论

1. 一切认知活动都视为计算，基本形式是：**对象 + 操作 → 新对象**
2. 对象不是预先固定的，计算产生的新对象可以继续成为下一次计算的对象
3. 计算中包含计算：识别、搜索、应用、验证、评价、选择验证方式……都是同一递归过程在不同对象上的表现
4. 不设计独立的"识别/搜索/评价/验证/创造力"模块
5. 允许尝试各种命题结构和变换，生成后再通过验证判断是否成立
6. 错误结果停止当前分支；正确结果保留为知识
7. **正确但暂时无用的知识不能删除**，只降低当前调用价值
8. 严格区分：命题是否成立 / 命题在当前目标下是否有价值
9. 知识空间不是预先建立的数据库，而是历史计算不断产生并保留的对象、命题、操作和验证结果
10. 初始系统只需要极少先验：基本对象、基本命题形式、基本变换能力、一个初始目标

## 二、项目结构

```
cognition/

├── environment.py      # 人工世界（球/盒子/桌子/墙，隐藏转移规则）

experiments/

tests/test_core.py      # 15 个单元测试

results/                # 实验结果（摘要 + 完整 trace/store）
```

## 三、计算机制

```
recursive_compute(object, goal, context):
  1. 识别/解析对象                       （也是计算）
  2. 从已有操作中产生候选变换             （也是计算，记录）
  3. 应用变换 → 生成 O'
  4. 验证 O'                             （错误→停分支；成立→保存）
  5. 评价 O' 对当前目标的价值            （有价值→继续；无价值→保留但降优先级）
  6. 递归：O' 成为新的计算对象
```

**搜索 = 寻找能作用于当前对象的计算结构；生成 = 应用之。二者属同一过程。**

## 四、知识库字段

每条知识记录：

| 字段 | 说明 |
|------|------|
| proposition | 命题 |
| status | valid / invalid / unknown |
| confidence | 置信度 |
| usefulness | 历史价值（None=未评价；数值=已评价） |
| evaluated | 是否经过价值评价 |
| usage_count / success_count | 使用次数 / 成功次数 |
| source | 由哪次计算产生 |
| parent_objects | 从什么对象产生 |
| operation | 使用了什么变换 |
| verification_method / verification_result | 验证方法 / 验证结果 |
| cost | 产生该知识消耗的计算资源 |

**重要约束：** `usefulness` 很低不会导致删除，只降低调用优先级。

## 五、验证系统

五种验证方法，每种本身也被追踪可靠性：

1. **逻辑验证** — 与已知 valid 事实的一致/矛盾
2. **规则验证** — 是否被已知 valid 规则覆盖
3. **重复案例验证** — 历史中共现比例
4. **预测后观察** — 预测规则的确认/反驳数
5. **反例验证** — 主动寻找反例

验证方法的可靠性由运行时共识（多数派）更新，**不使用 ground-truth**。

## 六、A/B/C/D 对照实验

| 组 | 生成 | 验证 | 价值评价 | 验证方法评价（元评价） |
|----|------|------|---------|----------------------|
| A | ✅ | ❌ | ❌ | ❌ |
| B | ✅ | ✅ | ❌ | ❌ |
| C | ✅ | ✅ | ✅ | ❌ |
| D | ✅ | ✅ | ✅ | ✅ |

**公平性保证：** 四组共享同一 environment、seed、初始知识、目标、输入序列、计算预算、先验操作集。唯一区别是三个布尔开关。

### 审计修复后的关键结果（10 seeds, mean ± std）

| 指标 | A | B | C | D |
|------|---|---|---|---|
| valid_correct | 0 | 24.3 ± 5.9 | 17.9 ± 3.6 | 19.0 ± 3.9 |
| error_rate | 0 | 0.245 ± 0.089 | 0.262 ± 0.095 | 0.250 ± 0.086 |
| total_cost | 3039 ± 24 | 4181 ± 152 | 2344 ± 175 | 2632 ± 96 |
| yield_per_cost | 0 | 0.0058 | 0.0076 | 0.0072 |

**核心发现（审计后）：**

- ✅ **生成**产生大量候选（A 组 800 条 unknown，无法判断对错）
- ✅ **验证**截断错误分支（B 组 invalid 显著）
- ✅ **价值评价**降低计算成本（C 比 B 便宜 44%）
- ❌ **"元评价降低错误率至 0"被推翻** — 移除事后 oracle 后，D 错误率 0.250 与 B/C 无显著差异。原 0 错误率是实验设计制造的假象。
- ❌ **"知识压缩降本 25%"归因错误** — 成本下降 100% 来自缓存（reuse_known 跳过验证），复合操作贡献 <3%

### 审计发现的实验漏洞

1. **验证器仍是"弱 oracle"** — 验证方法直接读取已观察历史判断命题是否成立，系统没有"提出验证方法→执行→获得证据→计算支持度"的闭环
2. **元评价效果不显著** — D 与 C 无显著差异，运行时反馈信号太弱
3. **复合操作质量低** — 挖掘出的是长序列噪声，confidence=0，未经验证
4. **统计样本偏小** — 每组 valid 蕴含约 25-32 条，置信区间较宽

## 八、理论的 10 条最终判断标准

1. 系统是否能从少量初始结构不断产生新命题？
2. 新命题是否经过验证后进入知识空间？
3. 正确但无用的知识是否能够保留？
4. 系统是否能根据目标改变知识调用优先级？
5. 系统是否能学习哪些验证方法可靠？
6. 系统是否能从失败中修改后续计算？
7. 系统是否能把反复成功的计算压缩成新的可调用计算结构？
8. 新结构是否能够反向展开到具体计算？
9. 随着知识增长，完成相同目标所需的计算量是否下降？
10. 系统是否能够在没有人为指定具体解决方法的情况下产生越来越有效的计算路径？

## 九、下一步实验计划（E0→E7）

1. **E0 知识空间长期增长** — 知识规模↑时计算成本↑还是↓？缓存饱和后会怎样？
2. **E1 深层递归学习** — 新命题是否成为新计算对象并产生有效知识？
3. **E2 压缩→调用→反向展开闭环** — 压缩后的操作能否展开回原计算？
4. **E3 目标切换** — 知识价值是否随目标重排而非固定属性？
5. **E4 操作自举** — 严格版：初始只给最基本变换，禁止人工加新操作
6. **E5 验证方法失效** — 让某验证方法逐渐失效，观察系统是否发现并切换
7. **E6 跨环境迁移** — A 世界学到的规则在 B 世界测试

## 十、先验声明

以下为系统初始注入的先验（非从计算中产生）：

- **基本对象**：ball, box, table, wall
- **命题形式**：原子/否定/合取/析取/蕴含/等价/关系/谓词/全称/存在
- **基本变换操作**：neg_intro, neg_elim, conj_elim, disj_intro, impl_intro, modus_ponens, modus_tollens, specialize, generalize, relation_swap, substitute, cooccur_impl_induce, seq_impl_induce
- **初始目标**：predict_next（预测下一状态）
- **评价维度权重**：relevance 0.5, generality 0.3, novelty 0.2

所有领域知识（如 Open(box)→CanTake(ball)）必须由系统从观察中产生并经验证保留，代码中无预置具体规则。
